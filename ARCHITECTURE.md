# Архитектура проекта

Магазин компьютерных комплектующих: каталог с поиском и фильтрами, корзина с расчётом и промокодом.
Статическое приложение на **Vite + TypeScript**, тесты — **Vitest**, публикация — **GitHub Pages**.
Доска задач: https://github.com/users/Al-E-xXx/projects/1

## Слои (подобие MVC без БД)

| Слой | Папка | Что живёт | Правила |
|------|-------|-----------|---------|
| **Model** | `src/models/` | Чистые функции бизнес-логики: корзина, фильтры/сортировка, маршруты + их тесты | Ничего не знает о DOM. Импортирует только типы. Всё покрыто юнит-тестами |
| **View** | `src/views/` | Только отрисовка: функции получают данные и колбэки, возвращают `HTMLElement` | Никаких вычислений и бизнес-решений. Не импортирует controllers/models (типы из `shared/` — можно) |
| **Controller** | `src/controllers/` | Склейка: обработчики событий, маршрутизация. Вызывают model, пишут в store, store дёргает view | Единственное место с `addEventListener` |
| **Данные** | `src/data/` | Статический список товаров («наша БД») | Только данные |
| **Общее** | `src/shared/` | Механизмы без предметной логики: `el()` (конструктор DOM), `Store<T>`, `formatPrice`, `debounce`, типы | Самый нижний слой: импортирует только типы. Если появляется слово «товар/корзина/промокод» — это уже model или view, выносим отсюда |

Правило зависимостей однонаправленное: `controller → model`, `controller → view`, все → `shared`.
`views` никогда не импортирует `controllers`, `models` не импортирует ничего, кроме типов.

## Дерево каталогов

```
src/
├─ main.ts                  # точка сборки: создать store, зарегистрировать страницы, запустить роутер
├─ shared/
│  ├─ dom.ts                # el(tag, attrs?, ...children) — надстройка над createElement
│  ├─ format.ts             # formatPrice(value) — вывод денег (презентация, не логика)
│  ├─ debounce.ts           # для поля поиска
│  ├─ store.ts              # generic Store<T>: getState / setState / subscribe
│  └─ types.ts              # Product, CartItem, Category и т.п.
├─ models/                  # бизнес-логика, рядом *.test.ts
│  ├─ cart.ts               # addToCart, setQuantity, removeItem, calculateTotal(items, promo)
│  ├─ products.ts           # filterProducts, sortProducts, поиск
│  └─ routes.ts             # parseRoute(hash) → 'about' | 'catalog' | 'cart' | '404'
├─ controllers/
│  ├─ router.ts             # hashchange → выбрать и смонтировать страницу; неизвестный адрес → 404
│  ├─ catalog.ts            # события поиска/фильтров/сортировки
│  └─ cart.ts               # «В корзину», +/−, удаление, промокод
├─ views/                   # каждая страница и компонент — папка с одноимёнными X.ts + X.css
│  ├─ about/                # about.ts, about.css
│  ├─ catalog/
│  ├─ cart/
│  ├─ notfound/
│  ├─ components/           # переиспользуемое: modal/, toast/, product-card/, quantity-stepper/, promo-form/
│  └─ layout/               # header.ts + header.css (меню, счётчик корзины), base.css
└─ data/
   └─ products.ts           # 8–12 комплектующих, минимум 2 категории
```

## Куда добавлять новое

| Ситуация | Место |
|----------|-------|
| Нужно одной странице (форма фильтров) | в папку этой страницы `views/<page>/` |
| Переиспользуемый визуальный компонент (модалка, карточка) | `views/components/<name>/` |
| Механизм без предметной логики (хелпер DOM, форматирование) | `shared/` |
| Правила расчёта, фильтрации, валидации | `models/` + тесты рядом |
| Обработчик события пользователя | `controllers/` |

Компонент едет в `views/components/`, если используется ≥2 страницами ИЛИ это механизм без предметной логики (modal, toast).

## Поток данных (пример «добавить в корзину»)

1. View карточки вызывает колбэк `onAdd(product)`, переданный контроллером;
2. Контроллер: `cartStore.setState(addToCart(cartStore.getState(), product))` — `addToCart` чистая функция;
3. Store уведомляет подписчиков — перерисовываются счётчик в шапке и (если открыта) страница корзины;
4. Сохранение в localStorage (задача позже) — подписчик store, никто другой хранилище не трогает.

## Деньги

Цены — целые (условные единицы). **Округления и скидки считаются только в models** (`calculateTotal`),
`shared/format.ts` лишь форматирует готовое число для вывода. В тестах расчёта не должно быть зависит от локали.

## Конвенции команды

- Каждая задача с доски — отдельная ветка от актуального `main`: `feat/<имя>`, `chore/<имя>`, `fix/<имя>`.
- До начала работы: назначить себя на issue и переместить карточку в **In Progress**; только потом ветка.
- Коммиты — Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `ci:`, `test:`), на английском.
- Заголовки issues и текст описаний — на русском (аудитория русскоязычная).
- Каждый PR: описание «что сделано / как проверить» и `Closes #<номер>` — тогда доска двигается сама.
- PR в `main` не мержится без ревью напарника; мержит ревьюящий. После мержа оба обновляют локальный `main`.
- Файл `package-lock.json` коммитится; ставим зависимости одними и теми же командами, Node.js ≥ 22.
- Структура папок меняется только вместе с обновлением этого файла (в том же PR).

## Команды

```bash
npm run dev       # локальный сервер разработки
npm run build     # проверка типов + production-сборка в dist/
npm test          # Vitest (проходит, пока тестов нет)
npm run preview   # локальный просмотр production-сборки
```
